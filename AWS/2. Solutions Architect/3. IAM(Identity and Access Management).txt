- What is IAM 
IAM allows you to manage users and their level of access to the AWS account
Create users and grant permissions to those users
Create groups and roles
Control access to AWS resources

It is important to understand IAM both for the exam and for administrating a companys AWS account in real life

- What is the Root Account
It is the email address you used to sign up for AWS. It has full administrative access to AWS. 
For this reason it is important to secure this account through MFA

- Tips
Enable MFA
Create an admin group for your administrators and assign the appropriate permissions to this group
Create user accounts for your administrators
Add your users to the admin group

- The Building Blocks of IAM
Users - A physical person
Groups - Functions, such as administrator, developer, etc. Contains users
Roles - Internal usage within AWS. To access one part of AWS from other part of AWS

- Best Practices: Policies
It is best practice for Users to inherit permissions from groups

- Best Practices: Users and People
Always work on the principle that one user equals one physical person. Never share user accounts across multiple people

- The Principle of Least Privilege
Only assign a user the minimum amount of privileges they need to do their job

- Console Demo

IAM EXAM TIPS

- Securing AWS Root Account
MFA on root account

Create user accounts for your administrators
Add your users to the admin group

- Assign Permissions Using IAM Policy Documents Consisting of JSON

- Permanent IAM Credentials
IAM is Universal - It dies not apply to regions at this time
The Root Account - The account created when you first setup AWS account and which has complete admin access. Secure it as soon as possible and do not use it to log in day to day
New Users - No permissions when created

Access key ID and secret keys are not the same as username and passwords - You cannot use the access key ID and secret access key to login to the console. However, you would use them to access AWS via APIs and CLI
You only get to view these once. If you lose them, you have to regenerate them. So, save them in a secure location
Always set up password rotations. You can create and customize your own password rotation policies

IAM Federation - You can combine your existing user account with AWS. For example, when you log on to your PC(usually using microsoft active directory), you can use the same credentials to login to AWS if you set up federation 
Identity Federation - Uses the SAML standard, which is Active Directory

LAB - CREATE AND ASSUME ROLES IN AWS

Two developers - user1 and user2
Four Buckets - appconfig1, appconfig2, customerdata1 and customerdata2

Create S3RestrictedPolicy and assign to user1
Create S3RestrictedRole and assign to user2
Role have 2 things - Permissions(What can you do) and Trust Policy(Who can assume it)

user1 need access through Policy attached to him and user2 need access through a Role assigned 

Policies > Create > S3 all actions > restrict all except bucket > Bucket add ARN > Paste bucket name in ARN of both buckets > Create > Select policy > Entities attached and add user1 > Attach policy
Roles > Create > AWS account > This account > Select the policy created above > Create > Select user2 > copy ARN > Select role > Trust relationship paste that arn and update
Assume the Role > Login user2 select top right and click switch role > account id and rolename
